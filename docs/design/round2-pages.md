# 2라운드 페이지별 개선안

방향, 모티브, 토큰은 [round2-direction.md](round2-direction.md). 토큰 이름은 그 문서 5장을 따른다.
현재 화면 근거는 `docs/design/shots/r1-after/`의 shop, product, me, login (모바일/PC x 라이트/다크)이다.
수용 기준은 visual-reviewer가 스크린샷을 보고 예/아니오로 채점한다. 각 페이지 끝의 **"달라 보이는가"** 항목은 before(r1-after)와 after를 나란히 놓고 채점한다.

## 범위

| 구분 | 화면 | 상태 |
|---|---|---|
| 이번 라운드 | 공통 헤더(1), 쇼핑 목록 `/`(2), 상품 상세(3), 내 활동 `/me`(4), 로그인/회원가입(5) | 개선안 + 수용 기준 |
| 다음 라운드(3라운드) | 관리자 `/admin/**`, `/me/account`, 다크 수동 토글 | 건드리지 않음. 공유 토큰이 깨지지 않는지만 확인 |

## 공통 제약

- 주문/결제 버튼은 처리 중 `disabled` + `aria-busy="true"` + 회전 링 + 진행 글자. 중복 클릭 방지(`inFlight` ref, 요청 하나당 멱등 키 하나)는 코드 그대로 둔다.
- PAYING/UNKNOWN은 확정 전 표시(`--unc` 점선, "결제 확인 중"). 취소/재결제 버튼 없음.
- AI 검색, 카테고리 트리, 활동 로그가 실패해도 목록/상세/주문 화면은 정상 레이아웃.
- 상품 응답에 있는 필드만 쓴다: `name, category(Label), subCategory(Label), price, originalPrice, discountRate, stock, soldOut, soldCount, description, thumbnail, perUserLimit`, 상세는 `detail, specs, images, related`. 장바구니, 찜, 리뷰, 알림은 만들지 않는다.
- 터치 영역 모바일 40px 이상(주요 버튼 48px 이상), 포커스 링 `:focus-visible` 2px `--focus`, 본문 4.5:1.

## 1. 공통 헤더

### 현재 문제
- `⚡` 이모지 + 글자 로고. 환경에 따라 아이콘이 다르게 나온다.
- 검색이 목록 본문 안에 있어 스크롤하면 사라지고, 상세/내 활동 화면에서는 검색할 수 없다.
- 모바일은 햄버거 안에 카테고리가 숨어 있다. 로그인 후 "내 활동" 알약 + 이름 버튼이 PC에서 무겁다(me.pc.light).
- 헤더가 흰 면 + 얇은 선이라 본문과 구분만 될 뿐 브랜드 인상이 없다.

### 개선안
1. **PC(너비 901px 이상)**: 높이 64px 한 줄. 왼쪽 로고(마크 28px + 워드마크), 가운데 검색 필드(최대 560px, 높이 44px, `--surface-2` 면, 테두리 없음, `:focus-within`에서 2px `--accent` 링), 오른쪽 내비.
2. 검색 필드: 왼쪽 돋보기 SVG, 입력, 값이 있을 때 지우기(×, 40x40 영역), 오른쪽 안에 원형 검색 버튼(36px, `--accent`, 돋보기 SVG, `aria-label="검색"`). 기존 `SearchBox`의 제출 동작(`navigate('/?q=...')`)을 그대로 쓰고 위치만 `Header`로 옮긴다. placeholder "예: 5만원 이하 무선 마우스". 예시 검색어 칩은 헤더에서 빼고 히어로(2장)에 둔다.
3. **모바일(900px 이하)**: 두 줄. 첫 줄(56px) 로고 + 내비, 둘째 줄(52px) 검색 필드. 헤더는 `position: sticky; top: calc(-1 * var(--header-row))`로 두어 첫 줄은 스크롤로 사라지고 검색 줄은 상단에 남는다. 햄버거 버튼과 카테고리 드로어는 없앤다(카테고리는 목록의 레일이 맡는다, 2장).
4. 내비(로그아웃): "로그인"(텍스트 링크, 높이 40px), "회원가입"(알약 `--accent`, 높이 40px). 로그인 상태: "내 활동" 텍스트 링크(PC만), 계정 메뉴 버튼은 이름 첫 글자가 들어간 원형 아바타(36px PC / 40px 모바일, `--accent-weak` 면 + `--accent-text` 글자). 이름은 메뉴 안 상단에 이미 `loginId`가 있으므로 메뉴 제목에 `이름님`을 추가한다. 관리자는 아바타 옆 "관리자" 링크(PC) 유지.
5. 헤더 면은 `--surface`, 아래 `1px solid var(--border)`. 스크롤 전후 변화 없음(그림자 없음).
6. 사이드바와 카테고리 드로어는 고객 화면에서 제거한다(2장). 관리자 레이아웃은 원래 사이드바를 쓰지 않으므로 영향 없다.

### 수용 기준
- [ ] 로고가 이모지가 아니라 둥근 사각형 마크 + "니즈샵" 글자로 보이는가?
- [ ] PC 헤더 가운데에 검색 필드가 있고, shop/product/me 어느 화면에서도 같은 위치에 있는가?
- [ ] 모바일 shop 스크린샷에서 헤더가 두 줄(로고+내비 / 검색)이고, 햄버거 버튼이 없는가?
- [ ] 로그아웃 상태에서 "로그인"과 "회원가입"이 PC/모바일 모두 한 줄에 겹침 없이 보이는가?
- [ ] 로그인 상태에서 이름 대신 원형 아바타(첫 글자)가 보이는가?
- [ ] 헤더의 검색 버튼, 회원가입 글자가 라이트/다크 모두 선명히 읽히는가?
- [ ] 모바일에서 헤더 안 모든 누를 곳이 약 40px 이상으로 보이는가?
- [ ] (포커스 스크린샷이 있다면) 검색 필드에 포커스가 가면 주황 테두리가 보이는가?
- [ ] 검색 요청이 실패한 상태(토스트 + 빈 목록)에서도 헤더와 목록 틀이 그대로인가?

## 2. 쇼핑 목록 `/`

### 현재 문제 (shop.pc.light, shop.mobile.dark를 직접 봄)
1. 첫 화면 상단 400px에 사진이 없다. 검색창, 예시 칩, 제목, 정렬 줄만 있어 가게 성격이 안 보인다.
2. 모든 카드가 같은 크기라 시선이 머물 곳이 없고, 가격이 상품명과 비슷한 비중이다.
3. 남은 수량과 품절이 작은 텍스트/배지다. 이 서비스의 핵심 정보가 가장 작다.
4. 232px 사이드바가 그리드 폭을 줄이고, 모바일에서는 햄버거 뒤에 숨는다. 이모지 아이콘은 환경에 따라 안 보인다.
5. 정렬/가격대/품절 제외가 얇은 줄 하나에 섞여 있다.
6. 빈 상태/로딩 상태가 평범한 글자와 회색 박스다.

### 개선안

**2-1. 히어로(홈, 필터와 검색어가 없을 때만)**
- 높이 PC 약 280px / 모바일 약 220px, 모서리 `--radius-xl`, 면 `--hero-bg`, 배경에 `radial-gradient`(오른쪽 위, accent 최대 30%)만. 이미지 파일 없음.
- 내용(위에서 아래): ① eyebrow 알약 "수량 한정 · 선착순 판매"(`--hero-chip` 면, `--hero-accent` 글자, 12px/700) ② 제목 `--fs-hero` / 800 / `--ls-hero`, 문구 "정해진 수량만큼만,<br>좋은 물건을 골랐어요"(2줄) ③ 보조 문장 `--hero-muted` 14px "재고가 모두 팔리면 판매가 끝나요. 남은 수량은 상품마다 그대로 보여드려요." ④ 예시 검색어 칩 4개(기존 `SUGGESTIONS`, `--hero-chip` 면, `--hero-fg` 글자, 높이 36px; 모바일은 한 줄 가로 스크롤).
- 문구는 제안이다. 판매 수치(예: "오늘 N개 판매")는 넣지 않는다(API에 없음).
- 히어로는 정적이다. 시간, 카운트다운, 애니메이션 없음. 검색/조건이 있는 화면에서는 히어로 대신 한 줄 제목(2-5)이 나온다.
- 상품 목록이 로딩 중이거나 실패해도 히어로는 그대로 보인다(상품 데이터에 의존하지 않음).

**2-2. 카테고리 레일 (사이드바 대체)**
- 히어로(또는 제목) 아래 한 줄. 칩: 전체 + 5개 카테고리. 칩은 높이 44px, 아이콘(SVG 20px) + 이름 + 개수(`--muted`, 12px), 모서리 pill, 비선택은 `--surface` + `1px solid var(--border-strong)`, 선택은 `--text` 면 + `--bg` 글자(라이트는 잉크 면, 다크는 밝은 면). 모바일은 가로 스크롤 + 오른쪽 끝에 다음 칩이 반쯤 보이게 하고 스크롤바는 숨긴다.
- 카테고리를 선택하면 레일 아래 둘째 줄에 소분류 칩(36px, 아이콘 없음, 선택은 `--accent-weak` 면 + `--accent-text` 글자 + 1px `--accent-text` 테두리)이 나온다. 소분류 개수 0이면 칩에 `--muted` 글자(흐리게 만들지 않는다).
- 데이터는 기존 `api.categories()` 응답(코드, 이름, 개수, 자식)을 쓴다.
- **실패 격리**: 트리 요청이 실패하면 "전체" 칩 하나만 보이고 안내 문구는 없다. 상품 그리드는 영향받지 않는다. 로딩 중에는 칩 자리에 같은 높이의 회색 알약 5개(스켈레톤)를 둔다.
- 선택 상태는 지금처럼 URL 쿼리(`category`, `sub`)가 기준이다. 변경 없음.

**2-3. "남은 수량이 적은 상품" 레일 (홈 무필터에서만, 있을 때만)**
- 불러온 목록(`products`)에서 `!soldOut && stock > 0 && stock <= LOW_STOCK_THRESHOLD`인 것을 `stock` 오름차순으로 최대 8개 뽑아 가로 레일로 보여준다. 서버 변경 없음.
- 제목 "남은 수량이 적은 상품"(18px/800), 보조 `--muted` "수량이 소진되면 판매가 끝나요". 카드는 그리드와 같은 카드를 폭 180px(모바일)/220px(PC)로 쓰고 `scroll-snap-type: x proximity`.
- 해당 상품이 0개면 섹션을 그리지 않는다(빈 자리도 남기지 않는다). 시간, 진행 막대, 불꽃 아이콘, 깜빡임 없음.

**2-4. 카드** (구조는 direction 3장)
- 이미지 위 왼쪽 아래: `stock <= 10`이고 품절이 아니면 "N개 남음" 칩(`--warn-weak`/`--warn`, 12px/700, pill, 높이 24px). 문구는 "N개 남음"만.
- 품절: 이미지 전체에 `--scrim` + 가운데 "품절"(`--on-scrim`, 15px/700, 자간 .04em), 가격은 `--muted`, 칩 없음. 이미지에 `opacity`를 낮추지 않는다(스크림이 대신한다).
- 가격 줄: `13%`(`--accent-text` 15px/800), `139,000원`(18px/800, tabular), 원가(12px `--muted` 취소선). 할인이 없으면 가격만.
- 1인 구매 제한이 있으면 가격 아래 12px `--muted` "1인 2개까지" 한 줄.
- 카드 전체가 링크(`<a>`), 이름은 `h3` 또는 기존 `h4` 유지. 포커스 링은 카드 이미지 모서리를 따라 바깥쪽.
- hover(포인터 기기): 이미지 1.04배 + `--shadow-lift`는 쓰지 않고 이미지만 확대한다(그림자는 대표 카드 제외 모두 생략해 목록이 조용하게 유지). `:active` 0.98배.

**2-5. 제목 줄과 도구줄**
- 히어로가 없을 때(검색, 카테고리, 필터 적용 화면): 빵부스러기(`홈 › 키보드`, 13px `--muted`) + 제목 `h2` 28px/800 + 개수 `--muted` 16px. 히어로가 있을 때는 제목 `h2` "전체 상품 25개"를 레일 아래 20px/800으로 둔다.
- 정렬 탭은 알약 세그먼트: 선택은 `--text` 면 + `--bg` 글자, 나머지는 투명 + `--muted`. 높이 40px. `role="tablist"`/`aria-selected` 유지.
- 가격대 `select`와 "품절 제외"는 정렬 오른쪽(PC) / 다음 줄(모바일)에 같은 높이 40px로 맞춘다.
- 조건 칩(`removable`)은 기존대로 `--accent-weak`/`--accent-text`, × 버튼 32px 이상. "이렇게 이해했어요" 줄은 도구줄 위 그대로.
- AI 검색 안내(`corrected`) 문구는 `--surface-2` 면의 둥근 박스(좌우 16px 여백)로 감싼다. 내용 변경 없음.

**2-6. 그리드**
- 1024px 이상: `repeat(auto-fill, minmax(220px, 1fr))`, 간격 `--space-6` 세로 / `--space-4` 가로. 홈 무필터일 때 첫 카드는 `grid-column: span 2; grid-row: span 2`(대표 카드: 이미지가 2x2, 이름 20px/700, 가격 22px/800). 열이 3 미만이면 대표 카드를 쓰지 않는다.
- 641~1023px: 3열. 640px 이하: 2열, 간격 `--space-5` 세로 / `--space-3` 가로. 대표 카드는 모바일/태블릿에서 일반 크기.
- 가격 줄 높이가 맞도록 이름은 2줄 고정 높이(`min-height: 2.7em`) 유지.

**2-7. 상태**
- 로딩: 카드 스켈레톤 8개(대표 카드 자리 포함하지 않고 일반 크기), 이미지 정사각형 + 이름 2줄 + 가격 1줄, shimmer. 히어로/레일/헤더는 이미 그려진 상태.
- 빈 결과: 가운데 정렬, 돋보기 SVG(64px, `--muted`), 제목 "조건에 맞는 상품이 없어요"(18px/700), 보조 문장, 예시 검색어 칩, 주 버튼 "전체 상품 보기"(`--accent`).
- 검색 실패(`searchFailed`): 같은 빈 상태 틀에 제목 "검색에 실패했어요", 보조 "잠시 뒤 다시 시도하거나 전체 상품을 둘러보세요", 버튼 "전체 상품 보기". 예시 칩은 숨김(현재 동작). 헤더, 레일, 히어로는 영향받지 않는다.
- 상품 목록 API 실패: 위 빈 상태와 같은 틀 + 제목 "상품을 불러오지 못했어요". 레이아웃은 무너지지 않는다.

## 3. 상품 상세 `/products/:id`

### 현재 문제 (product.mobile.light, product.pc.* 직접 봄)
1. 구매 제한이 설명 괄호("(1인 2개)", 데이터 문자열), 정보 표 "구매 제한 1인 2개", 칩 "1인 2개까지" 세 곳에 나온다.
2. 모바일에서 구매 버튼이 이미지, 썸네일, 설명, 가격, 재고, 표, 칩, 수량 아래 약 900px 지점이라 한 화면에 안 들어온다.
3. 구매 영역이 본문과 같은 면이라 "여기서 사는 곳"이 구분되지 않는다.
4. 가격(26px)과 상품명(22px) 크기가 비슷하고, 재고는 `facts`의 한 줄 텍스트다.
5. 상세 하단 안내 4줄 목록이 길어 스크롤이 길다.
6. 관련 상품이 한 장만 덩그러니 있다.

### 개선안

**3-1. 갤러리**
- PC: 좌측 큰 이미지(정사각형, 모서리 `--radius-xl`), 아래 썸네일 줄(64px, 선택은 2px `--accent` 링). 모바일: 이미지가 화면 좌우 끝까지(좌우 여백 0, 모서리 0), 아래 썸네일 줄 56px 가로 스크롤. 썸네일 클릭 동작(`imageIndex`)은 그대로.

**3-2. 구매 패널**
- PC: 오른쪽 폭 440px, `--surface` 면 + `1px solid var(--border)` + `--radius-xl` + 안쪽 `--space-5`, `position: sticky`(기존). 모바일: 패널 면/테두리 없이 본문에 이어지되 좌우 여백 `--space-4`.
- 위에서 아래 순서:
  1. 카테고리 링크(`키보드 › 기계식`, 13px `--muted`)
  2. 상품명 `h1` 26px/800/`--ls-tight`
  3. 한 줄 설명(`description`, `--muted` 14px, 모바일은 2줄 말줄임)
  4. 가격 블록: `13%`(`--accent-text` 20px/800) + 현재가 `--fs-3xl`/800 tabular + 원가 14px 취소선 `--muted`
  5. **상태 줄 한 곳**(구매 조건의 유일한 위치): 재고 상태 칩 + 구매 제한 칩을 같은 줄에 둔다.
     - `stock > 10`: `--muted` 텍스트 "재고 N개"
     - `1 <= stock <= 10`: "N개 남음" 칩(`--warn-weak`/`--warn`)
     - 품절: "품절" 칩(`--neutral-weak`/`--neutral`)
     - `perUserLimit`이 있으면: "1인 N개까지" 칩(`--info-weak`/`--info`) 한 개만.
  6. 수량 줄: `수량` + 스테퍼(− 숫자 +, 각 40x40, `--border-strong` 테두리) + 오른쪽 합계는 하단 구매 바로 옮기므로 여기서는 뺀다. 최대 수량에 닿으면 스테퍼 아래 `--muted` 12px "최대 N개"(`aria-live="polite"`)를 보인다.
  7. 구매 바(3-3)
  8. 안내 두 줄(12px `--muted`): "무료배송 · 결제 후 1~2일 내 출고" / "주문 후 10분 안에 결제하지 않으면 자동 취소돼요." (기존 코드 문구 `facts`와 안내 목록의 내용을 가져온 것)
  9. 로그아웃 상태면 "로그인하면 이 페이지로 다시 돌아와요."(기존)
- **구매 제한 정리**: `facts` 표(구매 제한, 배송 행)와 별도 `limit-chip` 문단을 삭제하고 5번 칩 하나로 통합한다. 배송은 8번 안내 줄로 옮긴다. 설명 괄호의 "(1인 2개)"는 시드 데이터 문자열이라 이 라운드에서 고치지 않는다(데이터 변경은 범위 밖). 화면에는 칩 하나 + 데이터 설명 한 번만 남는다.

**3-3. 구매 바와 모바일 하단 고정**
- 구매 바는 **DOM에 하나만** 둔다: 합계(라벨 "합계" 12px `--muted` + 금액 20px/800 tabular)와 구매 버튼. 별도의 "고정용" 복제 버튼을 만들지 않는다.
- PC: 구매 패널 안에서 합계 줄 아래 버튼이 가로 전체(높이 52px).
- 모바일(900px 이하): 같은 요소가 `position: fixed; left:0; right:0; bottom:0`, 높이 `--bar-h`(72px) + `padding-bottom: env(safe-area-inset-bottom)`, 면 `--surface`, 위쪽 `1px solid var(--border)` + `--shadow-bar`. 왼쪽 합계(수량에 따라 갱신), 오른쪽 버튼(`flex: 1`, 최소 폭 180px, 높이 52px). 페이지 아래에 `padding-bottom: calc(var(--bar-h) + 16px + env(safe-area-inset-bottom))`를 줘서 마지막 섹션이 가려지지 않게 한다. 토스트는 이 구간에서 바 위(`bottom: calc(var(--bar-h) + 12px)`)로 올린다.
- **중복 클릭 방지는 현재와 같다(필수)**: 버튼은 하나이고 `buy()`의 `inFlight` ref, `disabled={blocked || ordering}`, `aria-busy={ordering}`, 한 번의 클릭당 `crypto.randomUUID()` 하나를 그대로 쓴다. 바를 고정한다고 클릭 핸들러가 늘어나지 않는다. 진행 중에는 회전 링 + "주문 중…", `--accent-hover` 배경. 품절이면 `--disabled-bg`/`--disabled-fg`의 "품절". 로그아웃이면 "로그인하고 구매하기"(기존 이동 동작). 수량 스테퍼도 진행 중에는 비활성으로 둔다(`disabled={blocked || ordering}`로 바꾸는 것을 권장: 결제 중 합계가 바뀌지 않게).
- 키보드 포커스 순서는 스테퍼 → 구매 버튼이다. 고정 바가 있어도 이미지/썸네일보다 DOM 순서가 뒤여야 한다.

**3-4. 본문 섹션**
- "상품 설명"(`h2` 20px/800, 아래 선 없음, 위 여백 `--space-7`), "상품 정보" 표(첫 열 `--surface-2` 면 + `--muted`, 행 사이 `--border`, 모서리 `--radius-lg`로 감싼 박스, 모바일 첫 열 120px).
- "배송 · 교환 · 반품 안내"는 `<details>`(접이식, 기본 닫힘, 요약 줄 높이 56px, 오른쪽 화살표 SVG). 안 내용은 기존 4줄. 결제 기한 안내는 3-2의 8번에 이미 있다. JS 없이 동작한다.
- 관련 상품: 제목 "같은 카테고리 상품". 모바일은 가로 스크롤 레일(카드 폭 160px, snap), PC는 목록과 같은 그리드. 카드는 2장 카드와 같다. 1장이어도 같은 카드 폭이라 어색하지 않다.

**3-5. 상태**
- 로딩: 왼쪽 정사각형 스켈레톤 + 오른쪽 패널 스켈레톤(줄 4개 + 버튼 모양). 구매 바는 스켈레톤 동안 그리지 않는다.
- 404: 기존 빈 상태 틀(돋보기 대신 상자 SVG) + "상품 목록으로" 버튼.

## 4. 내 활동 `/me`

### 현재 문제 (me.pc.light 직접 봄)
1. 주문 박스, 최근 검색어, 최근 본 상품이 같은 비중으로 세로 나열되고, PC에서는 화면 오른쪽 절반이 비어 있다.
2. 주문 카드: 작은 상태 알약, 회색 날짜, 긴 주문번호가 한 줄에 섞여 있다. 금액은 카드 왼쪽 아래에 있어 시선이 흩어진다.
3. 상태별 안내가 `muted` 문장 하나라서 "결제 확인 중"과 "취소됨"이 비슷하게 보인다(확정 전은 달라 보여야 한다).
4. 빈 상태가 글자 한 줄이다. 헤더 "내 활동" 제목 아래 인사나 요약이 없다.

### 개선안
1. **레이아웃**: 최대 폭 1120px, PC는 2열(주문 `minmax(0, 1fr)` / 보조 정보 320px, 간격 `--space-6`), 모바일은 한 열(주문이 먼저). 사이드바 제거로 폭이 늘어난 것을 이 구조가 채운다.
2. **페이지 머리**: `h1` "내 활동" 28px/800, 아래 `--muted` 14px "김철수님의 주문과 최근 활동이에요"(세션 이름 사용).
3. **주문 카드**(`--surface`, `--border`, `--radius-lg`, 안쪽 `--space-5`/모바일 `--space-4`):
   - 윗줄: 상태 알약(왼쪽), 날짜(오른쪽, 13px `--muted`, 모바일은 줄바꿈).
   - 가운데: 상품 행(이름 링크 16px/600 + `× 수량`, 단가 `--muted` 13px). 썸네일은 주문 응답에 없으므로 쓰지 않는다.
   - 아랫줄: 왼쪽 "주문번호 …"(12px `--muted`, 긴 번호는 말줄임 없이 줄바꿈 허용 `word-break: break-all`), 오른쪽 합계 20px/800 tabular.
4. **상태 알약**(글자가 항상 같이 있고, 색만으로 구분하지 않는다): 결제 대기 `--info`, 결제 완료 `--good`, 주문 취소/기한 만료 `--neutral`, **결제 확인 중(PAYING) `--unc` + 점선 테두리 + 속 빈 링 점**. 높이 28px, 14px/600.
5. **상태별 하단 영역**(카드 맨 아래, 면 박스):
   - 결제 대기: `--info-weak` 박스, 왼쪽 "10분 안에 결제하면 주문이 확정돼요 · 결제 기한 m:ss"(기존 `Countdown` 값을 `--muted` 일반 글자, 숫자 tabular로. 새 강조색, 깜빡임, 크기 확대 없음), 오른쪽 "결제하기" 버튼(모바일은 박스 아래 전체 폭 48px). 처리 중은 `disabled` + `aria-busy` + 회전 링 + "결제 중…", `paying` 상태 그대로.
   - **결제 확인 중(PAYING)**: `--unc-weak` 면 + `1px dashed var(--unc)` 박스, 속 빈 링 점 + "결제 결과를 확인하고 있어요. 잠시만 기다려주세요."(기존 문구 유지). **버튼 없음**(취소, 재결제, 새로고침 버튼 모두). 완료/실패처럼 보이는 초록, 빨강, 체크, X 아이콘을 쓰지 않는다. 점은 `prefers-reduced-motion: no-preference`일 때만 천천히 숨 쉬는 효과(불투명도 .5~1, 2초)를 허용한다. 카드의 상태 알약과 박스의 점선이 같아 확정 전임이 두 번 드러난다. 같은 처리가 결제 UNKNOWN(결제 상태)에도 적용되나 `/me`는 현재 주문 상태만 보여주므로 이번엔 PAYING만 해당.
   - 결제 완료: 박스 없음(알약이 `--good`). 
   - 기한 만료/취소: `--neutral-weak` 박스 + 기존 문구(만료 "결제 기한이 지나 주문이 자동 취소되었어요." / 취소 "취소된 주문이에요. 결제하셨다면 환불이 진행됩니다.").
6. **보조 열**: "최근 검색어"(칩 줄, 없으면 `--muted` 한 줄 "최근 검색한 기록이 없어요."), "최근 본 상품"(2열 소형 카드 그리드; 모바일은 가로 레일). 활동 로그 응답이 실패하면(현재 동작: 빈 값으로 대체) 보조 열은 안내 한 줄만 보이고 주문 열 레이아웃은 그대로다. 주문 목록이 비면 보조 열 없이도 주문 열이 폭을 유지한다.
7. **빈 주문**: 상자 SVG 아이콘 + "아직 주문한 상품이 없어요" + 주 버튼 "상품 보러가기"(`--accent`, 높이 44px).
8. 로딩: 주문 카드 모양 스켈레톤 2개("불러오는 중…" 글자 대신).

### 수용 기준
- [ ] PC에서 주문 목록이 왼쪽 큰 열, 최근 검색어/최근 본 상품이 오른쪽 좁은 열로 나뉘어 화면 폭을 쓰는가? (오른쪽 절반이 비어 있지 않은가)
- [ ] 주문 카드에서 합계 금액이 오른쪽 아래에서 가장 큰 글자(약 20px 굵게)로 보이는가?
- [ ] 상태 알약이 `결제 완료`는 초록, `결제 대기`는 파랑, `취소/만료`는 회색으로 글자와 함께 보이는가?
- [ ] (PAYING 캡처가 있을 때) "결제 확인 중"이 보라 점선 알약/박스이고, 초록/빨강/체크/X 표시가 없고, 취소/재결제/결제하기 버튼이 없는가?
- [ ] (결제 대기 캡처가 있을 때) 결제 기한 숫자가 평범한 글자로 보이고(빨강, 깜빡임, 큰 글자 아님) "결제하기" 버튼이 박스 안에 있는가?
- [ ] (결제 중 캡처가 있을 때) "결제 중…" 글자와 회전 링이 보이는가?
- [ ] 활동 데이터가 비어도 주문 영역이 그대로이고, 보조 열은 한 줄 안내만 있는가?
- [ ] 모바일 390px에서 주문이 먼저, 그 아래 검색어/최근 본 상품이 세로로 이어지고 가로 스크롤이 없는가?
- [ ] axe `color-contrast` 0건인가?

**달라 보이는가 (before: r1-after/me.\*와 비교)**
- [ ] PC가 1열 → 2열로 바뀌었는가?
- [ ] 주문 카드에 상태별 하단 박스(안내/버튼)가 있어 상태가 한눈에 구분되는가?
- [ ] 두 항목 모두 "예"이면 "확연히 달라 보임".

## 5. 로그인 `/login`, 회원가입 `/signup`

### 현재 문제 (login.pc.light 직접 봄)
1. 중앙 흰 카드 하나. 로고나 환영 문구가 없고 헤더 아래 허공에 떠 있다.
2. 데모 계정 영역이 폼 아래에서 폼만큼의 면적을 차지한다.
3. 회원가입은 입력이 5개라 모바일에서 길다(검증 문구 12px).

### 개선안
1. 배경: 페이지 바탕 위쪽에 accent 최대 20% `radial-gradient` 글로우(PC 상단 360px, 모바일 240px). 이미지 없음. 글로우 위에 글자를 직접 얹지 않는다(글자는 카드 안에만 있다).
2. 카드: `--surface`, `--radius-xl`, `--shadow-lift`(약한 단계 `0 8px 24px` 정도), 폭 `min(440px, 100%)`, 안쪽 `--space-6`/모바일 `--space-5`. 맨 위에 로고 마크(40px) 가운데, 아래 `h1` "로그인"(24px/800), 한 줄 설명 `--muted` "계속하려면 로그인하세요"(가입 화면은 "니즈샵 회원이 되어 보세요").
3. 입력칸 높이 48px(PC 44 이상 유지), `--radius`, 테두리 `--border-strong`. 포커스는 바깥 2px `--focus`. 라벨 위, 오류는 `--bad` + 글자.
4. 제출 버튼 높이 52px, 3상태는 1라운드 규칙 유지(정상 / 입력 대기 `disabled` 회색 / 진행 중 `aria-busy` + 링 + "로그인 중…", "가입 중…").
5. 데모 계정 영역: 카드 아래 구분선 + 제목 "데모 계정으로 체험하기"(13px/600), 면 없이 `1px dashed var(--border-strong)` 박스, 버튼은 한 줄씩 유지. 제출 버튼보다 시각적으로 약해야 한다. (표시 조건은 기존 코드 그대로, 이 문서는 운영 노출 정책을 바꾸지 않는다.)
6. 회원가입: 같은 카드. 비밀번호 도움말/검증 문구는 13px. 입력 간격 `--space-4`. 에러는 입력 바로 아래 `--bad` 13px 글자.
7. 모바일: 카드 폭 100%(좌우 여백 `--space-4`), 헤더 아래 `--space-5`부터 시작.

### 수용 기준
- [ ] 카드 맨 위에 로고 마크와 큰 제목이 보이는가?
- [ ] 카드 바깥 배경에 은은한 주황 글로우가 보이고 글자와 겹치지 않는가?
- [ ] 입력칸 높이가 약 48px로 before보다 커졌는가, 테두리가 보이는가?
- [ ] 비어 있을 때 "로그인" 버튼이 회색 비활성인가?
- [ ] (진행 중/에러 캡처가 있을 때) "로그인 중…"/"가입 중…" 글자 + 링, 에러는 붉은 박스/글자로 보이는가?
- [ ] 데모 계정 영역이 점선 박스로 제출 버튼보다 덜 눈에 띄는가?
- [ ] 모바일 390px에서 가로 스크롤이 없는가?
- [ ] axe `color-contrast` 0건인가?

**달라 보이는가 (before: r1-after/login.\*와 비교)**
- [ ] 로고 + 제목 위계, 큰 모서리와 그림자, 배경 글로우 중 2개 이상이 before와 다르게 보이는가?

## 승인이 필요한 항목

- 새 라이브러리: 없음. 웹폰트 외부 로드: 없음(시스템 스택 그대로).
- 백엔드 필요(이번 범위 밖): 상품 목록의 서버 측 "재고 적은 순" 정렬, 히어로의 판매 실적 수치, 재입고 알림, 찜/장바구니, 주문 응답의 상품 썸네일(내 활동 주문 카드 이미지).

## 사용자 판단이 필요한 항목

1. **좌측 사이드바 제거**(고객 화면 전체)와 모바일 햄버거 제거를 가로 카테고리 레일로 바꾸는 것. 카테고리 이동 방식이 바뀌는 가장 큰 변경이다.
2. **히어로 문구와 어두운 히어로 면**: "정해진 수량만큼만, 좋은 물건을 골랐어요", "수량 한정 · 선착순 판매". 브랜드 톤이므로 사용자 취향 확인이 필요하다.
3. **"남은 수량이 적은 상품" 레일**과 카드의 "N개 남음" 노출(기준 10개 이하는 1라운드 제안값 유지). 재고를 더 크게 드러내는 것이 경쟁 구매를 부추기는지 판단이 필요하다. 시간 압박 요소는 없다.
4. **홈 첫 카드 2x2 대표 카드**: 인기순 1위가 자동으로 대표가 된다. 의도한 상품을 대표로 두려면 백엔드 필요(범위 밖).
5. **데모 계정 영역** 표시를 유지하는가(현재 코드 동작 그대로, 스타일만 약화).
6. 상세 설명 데이터에 "(1인 2개)" 같은 구매 제한 문구가 박혀 있다. 이번 라운드에서는 데이터를 고치지 않는다.
7. 다크 팔레트를 차가운 회색에서 따뜻한 먹색으로 바꾸는 것(관리자 화면도 같은 토큰이라 함께 따뜻해진다).
