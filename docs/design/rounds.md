# UI 개편 라운드 기록

브랜치 `feature/ui-overhaul`. 범위는 `frontend/`뿐이다. 백엔드, API 계약, Flyway, 결제·재고·주문 로직은 바꾸지 않는다.
측정 환경: 백엔드 H2 기본 프로필(시드 상품 25개), Vite dev 서버, Playwright 1.63 + axe-core 4.11. 고정 화면 12개 x 모바일(390)/PC(1280) x 라이트/다크 = 48장.

## 1라운드: 디자인 토큰, 쇼핑 목록, 상품 상세, 로그인, 회원가입

문서: [tokens.md](tokens.md), [pages.md](pages.md)
스크린샷: `shots/r1-before/`, `shots/r1-after/` (파일명 `<화면>.<mobile|pc>.<light|dark>.png`)

Before의 실패 33건 중 color-contrast가 32건이고(admin-activity 모바일 라이트는 color-contrast와 `scrollable-region-focusable`이 함께 걸림), `scrollable-region-focusable`은 2건(admin-activity 모바일 라이트/다크)이다. After에는 후자 2건만 남았다. 시각 점수는 Before 채점이 없어 After만 기록한다.

### 라운드 진행

1. designer: 토큰과 페이지별 개선안, 수용 기준 작성. 접근성 실패 대부분이 주황 버튼 위 흰 글자(라이트 3.58:1)에서 나온다고 추정했고, 구현 뒤 axe 재측정으로 확인됐다.
2. frontend-coder: 토큰과 5개 화면 적용. 빌드, 린트 통과.
3. frontend-tester: 33건 실패 중 31건 해소, 흐름 회귀 없음.
4. frontend-reviewer: 중간 1건, 낮음 2건.
   - 중간: 같은 검색어에서 AI 검색이 실패한 뒤 성공(0건)해도 "검색에 실패했어요."가 남음 → 수정
   - 낮음: 상세에서 `soldOut=false, stock=0`이면 "0개 남음" 표시 → 수정
   - 낮음: "결제하기" 처리 중 `aria-busy` 없음 → 수정
5. visual-reviewer: 1차 채점에서 shop이 6~7점이었으나 **측정 오류**였다. `loading="lazy"` 이미지가 `fullPage` 캡처 때 로드되지 않은 채 찍혀서 카드가 빈 사각형으로 보였다. 앱 문제가 아니라 캡처 문제여서 하네스(`e2e/lib.mjs`의 `settle`)를 고치고 before/after를 모두 다시 찍어 재채점했다.
6. 재검증: 수정 3건 해소, 새 높음·중간 문제 없음. 자동 검사 3회 반복 결과 동일.

### 확인하지 못한 것

- 이미지 없는 카드의 카테고리 글자 placeholder, "N개 남음" 칩: 시드 데이터에 해당 상품이 없어 화면에서 확인하지 못했다(코드와 리뷰로만 확인).
- 구매 중("주문 중…"), 로그인/가입 에러, 품절 상세의 비활성 버튼, 키보드 포커스 링, 모바일 메뉴 열린 상태: 스크린샷이 없다.
- MySQL 환경과 백엔드 테스트는 이번 변경이 백엔드를 건드리지 않아 돌리지 않았다. CI 전체 결과는 PR에서 확인한다.
- 측정은 H2 시드 데이터와 Vite dev 서버 기준이다. 운영 빌드(Caddy 서빙)에서의 확인은 하지 않았다.

### 사용자 확인이 필요한 항목

1. 상품 목록 카드에 남은 재고 수량("N개 남음", 재고 10개 이하)을 노출해도 되는가. 상세 페이지에는 이미 정확한 재고가 보이고 API 변경은 없다. 임계값 10은 제안값이다.
2. 상품 상세에서 구매 제한이 설명 문구, 정보 표, 칩 세 곳에 나온다. 구매 박스가 길어져 모바일 구매 버튼이 before보다 약 50px 아래로 내려갔다. 칩을 없애거나 표 항목을 빼는 안을 2라운드에 넣을지 정해야 한다.
3. 비활성 버튼 스타일을 전역 규칙으로 바꿨다. 관리자 화면의 비활성 버튼 모양은 스크린샷에 비활성 상태가 없어 확인하지 못했다. 2라운드에서 확인한다.

### 후속(낮음, 필수 아님)

- AI 검색 실패 시 이전 성공 검색의 "이렇게 이해했어요" 칩이 남을 수 있다 (`ShopPage.tsx`, 기존 동작).
- 로그인 입력칸 포커스 링이 테두리와 겹쳐 두 겹으로 보인다.
- 2라운드 후보: 관리자 화면, 내 주문/계정, 다크 수동 토글, `admin-activity` 스크롤 영역 `tabIndex`, `admin-orders` 모바일 표 잘림, 토스트 토큰화.
