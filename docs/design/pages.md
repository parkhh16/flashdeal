# 페이지별 개선안 (1라운드)

토큰 이름과 값은 `docs/design/tokens.md`를 따른다. 스크린샷은 `docs/design/shots/r1-before/`의 `<화면>.<mobile|pc>.<light|dark>.png`를 직접 보고 쓴 것이다.

## 범위

| 구분 | 화면 | 상태 |
|---|---|---|
| 이번 라운드 | 공통 헤더/사이드바, 쇼핑 목록 `/`, 상품 상세 `/products/:id`, 로그인 `/login`, 회원가입 `/signup` | 개선안 + 수용 기준 |
| 다음 라운드 | 내 활동/주문 `/me`, 계정 `/me/account`, 관리자 `/admin/**` | 토큰 영향만 `tokens.md` 10번에 적음 |

## 공통 제약 (모든 페이지)

- 결제/주문/제출 버튼은 처리 중에 `disabled` + `aria-busy="true"` + 진행 표시("주문 중…")를 가진다. 이를 해치는 변경 금지.
- PAYING, UNKNOWN은 "확정 전"으로 보인다(`--unc` 점선). 실패나 완료로 보이게 하지 않는다. 이 상태에서 취소, 재결제 버튼 없음.
- AI 검색, 카테고리 트리, 활동 로그가 실패해도 상품 목록과 상세는 정상 레이아웃이다(자리 이동, 빈 화면 없음).
- 남은 수량과 품절은 사실 그대로 보여주되, 카운트다운, 판매율 막대, 깜빡임, "마감 임박" 같은 재촉 표시는 쓰지 않는다.
- API 필드, 서버 변경, 새 라이브러리 없음. 모든 안은 현재 응답의 `stock`, `soldOut`, `perUserLimit`, `categoryLabel`로 만든다.

## 1. 공통 헤더 / 사이드바

### 현재 문제
- (코드, 계산) 헤더 "회원가입" 버튼이 모든 화면 라이트에서 흰 글자 / `#e8590c` = 3.58:1, 다크에서 흰 글자 / `#ff8a3d` = 2.35:1로 axe `color-contrast` 실패. 보지 않은 화면을 포함해 헤더가 있는 모든 화면에 반복된다.
- (스크린샷 shop/product/login 전 변형) 헤더 로그인/회원가입 구성은 문제없이 정렬돼 있으나, `button.ghost`나 링크에는 키보드 포커스 링이 없다(`index.css`는 `input:focus`, `select:focus`만 정의).
- (shop.pc.*) 사이드바 "전체"가 검정(라이트)/흰색(다크) 알약으로 활성 표시되는 건 명확하다. 다만 소분류 `0개`는 `opacity: .5`로 글자가 흐려진다(약 1.97:1).
- (shop.mobile.*) 모바일 헤더는 햄버거, 브랜드, 로그인, 회원가입이 한 줄에 들어가 있고 문제 없다. 햄버거(`☰`)와 사이드바 `+`/`−` 토글은 터치 영역이 작다(`padding: 4px 8px`, 약 34x28px).

### 개선안
1. `.header-cta`와 기본 `button`의 글자색을 `--on-accent`, 배경을 `--accent`, hover를 `--accent-hover`로 바꾼다. (라이트 5.18:1, 다크 7.93:1)
2. 모든 `a`, `button`, `input`, `select`에 `:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px }`.
3. `.side-item.empty`는 `opacity` 대신 `color: var(--muted)`.
4. 모바일(`max-width: 900px`)에서 `.icon-btn`, `.header-nav a`, `.side-item`은 최소 40px 높이/너비.
5. 헤더 배경은 `--surface`, 아래 테두리 `--border` 유지. 계정 메뉴 그림자는 `--shadow-2`.

### 수용 기준 (visual-reviewer: 예/아니오)
- [ ] 라이트와 다크 모두에서 헤더의 "회원가입" 버튼 글자가 배경과 분명히 구분되어 읽히는가? (라이트: 흰 글자 / 진한 주황 `#c2410c`, 다크: 어두운 글자 / 밝은 주황)
- [ ] 다크 모드의 "회원가입" 버튼 글자가 흰색이 아니라 어두운 색인가?
- [ ] 로그아웃 상태 헤더가 PC와 모바일 모두에서 브랜드, 로그인, 회원가입이 한 줄에 겹침 없이 보이는가?
- [ ] 모바일에서 햄버거 버튼이 손가락으로 누를 수 있는 크기(약 40px 이상)로 보이는가?
- [ ] 사이드바에서 현재 선택된 항목이 한 곳만 강조되어 있고, 그 항목의 글자가 읽히는가?
- [ ] (소분류를 펼친 상태) 상품이 0개인 소분류도 글자가 흐릿하지 않고 읽히는가?
- [ ] 키보드로 Tab을 눌렀을 때 현재 포커스된 링크/버튼에 눈에 띄는 테두리가 보이는가? (포커스 스크린샷이 있을 때만 채점)

## 2. 쇼핑 목록 `/`

### 현재 문제 (shop.pc/mobile × light/dark를 직접 봄)
1. **이미지 없는 카드가 빈 회색 사각형이다.** 25개 중 상당수(PC 라이트 기준 3~7행의 대부분)가 이미지 없이 연한 회색 칸만 보인다. 카테고리 이모지가 스크린샷에는 안 나온다(이모지 폰트가 없는 환경). 다크에서는 칸이 배경(`#111317` 대 `#22262e`)에 거의 묻혀 "로딩 실패"로 보인다. 어떤 상품인지 이미지 칸만으로는 알 수 없다.
2. **남은 수량이 목록에 없다.** 재고가 한정된 상품 쇼핑몰인데 카드에는 `품절` 배지뿐이고, 3개 남았는지 100개 남았는지 상세에 들어가야 안다. (`Product.stock`은 목록 응답에 이미 있다.)
3. **품절 표시가 이미지 위 배지에만 의존한다.** 품절 카드(32인치 4K 모니터)는 이미지가 흐려지고 배지가 달리지만, 이미지가 없는 품절 상품이라면 배지만 남고 가격은 일반 상품과 똑같이 굵다.
4. **검색창이 무겁다.** 2px `--text` 색 테두리(라이트 검정, 다크 흰색)가 페이지에서 가장 강한 선이다. 모바일에서는 placeholder가 "찾는 상품을 말하듯이 입력해보세…"로 잘리고, 예시 칩이 바로 아래 있어 중복이다.
5. **대비 실패(계산)**: 검색 버튼 흰 글자 3.58:1(라이트), 다크 2.35:1. 칩 `.chip.static`/`.chip.removable` accent 글자 3.24:1.
6. 정렬 탭(`인기순/낮은가격순/높은가격순`)은 활성 상태가 굵기 차이뿐이라 모바일에서 구분이 약하다(shop.mobile.light).
7. 할인율이 `--bad` 빨강이라 "에러/품절"의 빨강과 같은 의미로 읽힌다.
8. 가격 12px 원가(`.original`), 카테고리 줄(`.cat`) 등 12px 보조 글자는 `--muted` 4.51:1로 통과 여유가 거의 없다.

### 개선안
1. **이미지 자리(placeholder)**: `ProductImage`가 이미지가 없거나 실패하면 `--surface-2` 배경 + `1px solid var(--border)` + 카테고리 아이콘(48px) 아래에 카테고리 이름 텍스트(`--fs-sm`, `--muted`, 예: "키보드")를 같이 보여준다. 이모지가 안 그려져도 텍스트로 어떤 칸인지 알 수 있다. 이름은 `ProductCard`가 가진 `product.categoryLabel`을 prop으로 넘긴다(API 변경 없음). 접근성 이름(`aria-label`)은 상품명 그대로.
2. **남은 수량 한 줄**: 카드 가격 아래에 `stock <= 10`이고 품절이 아니면 `N개 남음`을 `--warn` 글자 + `--warn-weak` 배경의 작은 칩(`--fs-xs`, `--radius-pill`)으로 보여준다. 10개 초과면 아무것도 보이지 않는다(조용하게). 문구는 "N개 남음"만 쓴다. "마감 임박", "곧 품절", 불꽃 아이콘, 깜빡임, 남은 시간은 쓰지 않는다. 10이라는 기준은 디자인 제안값이며, 원하면 `3 / 5 / 10`으로 바꿀 수 있게 상수 하나로 둔다.
3. **품절 카드**: 이미지 위 `품절` 배지(`--soldout-bg`, `--on-solid`)와 이미지 `opacity: .55`는 유지한다. 가격은 `--muted`로 낮추되 글자는 읽히는 대비(5.7:1 이상)를 지킨다. 품절 카드에 "N개 남음" 칩은 없다.
4. **검색창**: 테두리 `1px solid var(--border-strong)`, `:focus-within`일 때 `2px solid var(--accent)`. placeholder는 `예: 5만원 이하 무선 마우스`(짧게. 설명은 아래 예시 칩이 맡는다). 검색 버튼은 토큰의 accent 버튼(5.18/7.93:1).
5. **칩**: 조건 칩(`removable`, `static`)은 `--accent-weak` 배경 + `--accent-text` 글자. 칩의 × 버튼은 터치 영역 32px 이상.
6. **정렬 탭**: 선택된 탭은 굵게 + 아래 2px `--accent` 밑줄, 나머지는 `--muted`. `aria-selected`는 그대로.
7. **할인율**은 `--accent-text`, 가격은 `--text`. 원가는 `--muted` 취소선.
8. **그리드**: PC `repeat(auto-fill, minmax(200px, 1fr))`, gap `24px 16px`(`--space-5` `--space-4`). 모바일 2열, gap `20px 12px`에서 `--space-5 --space-3`로. 카드 간 정렬이 어긋나지 않도록 제목은 2줄 고정 높이(`min-height: 2.7em`)로 두어 가격 줄이 같은 높이에 맞는다.
9. **부가 기능 실패 격리**: AI 검색이 실패하면 현재처럼 토스트 + 빈 목록이 되는데, 목록 영역에 "검색에 실패했어요. 전체 상품 보기" 링크가 있는 빈 상태를 보인다(기존 `.empty`). 카테고리 트리가 실패해도 사이드바는 "카테고리를 불러오는 중…" 대신 빈 상태로 접히고 상품 그리드는 영향받지 않는다.
10. 페이지 제목 줄: `h2`(22px) + 개수(`--muted`, 15px). 현재 구조 유지.

### 수용 기준
- [ ] PC 라이트 shop에서 이미지가 없는 상품 카드 칸에 카테고리 이름 글자(예: "키보드", "모니터")가 보이는가?
- [ ] 다크 shop에서 이미지 없는 카드 칸의 경계가 배경과 구분되어 보이는가? (테두리 또는 면 차이)
- [ ] 남은 수량이 10개 이하인 상품 카드에만 "N개 남음" 표시가 있고, 11개 이상 카드에는 수량 표시가 없는가?
- [ ] "N개 남음" 표시에 시간, 카운트다운, 막대, 불꽃/경고 아이콘이 없는가?
- [ ] 품절 상품 카드에 "품절" 글자가 읽히는가? (라이트와 다크 모두 흰 글자 / 짙은 회색 배경)
- [ ] 품절 카드에 "N개 남음" 표시가 같이 나오지 않는가?
- [ ] 할인율(예: 13%)이 빨강이 아니라 주황/갈색 계열로 보이는가?
- [ ] 검색창 테두리가 얇은 회색 선이고, 검색 버튼의 글자(검색)가 라이트/다크 모두 선명히 읽히는가?
- [ ] 모바일(390px)에서 검색창 placeholder가 말줄임표 없이 전부 보이는가?
- [ ] 모바일 shop이 2열이고 가로 스크롤이 없는가?
- [ ] 정렬 탭 중 선택된 것이 굵은 글자 외에 밑줄로도 구분되는가?
- [ ] 같은 줄의 카드들에서 가격 줄 높이가 서로 어긋나지 않는가?
- [ ] 라이트/다크 모두에서 "전체 상품 25개" 제목, 정렬 탭, 가격대 선택, "품절 제외" 체크박스가 한 눈에 구분되는가?

## 3. 상품 상세 `/products/:id`

### 현재 문제 (product.* 4변형을 직접 봄)
1. **대비 실패 6건(라이트)**: "상품 정보" 표 머리 4칸(`--muted` / `--surface-2` 4.31:1) + "로그인하고 구매하기" 버튼 3.58:1 + 헤더 회원가입 3.58:1. 다크 2건은 구매 버튼과 헤더 버튼의 흰 글자 2.35:1.
2. **재고가 평범한 줄이다.** "재고 / 100개 남음"이 `facts` 목록 첫 줄이고 다른 행과 똑같이 보인다. 재고가 적을 때와 품절일 때도 시각적으로 구분되지 않는다(품절은 글자만 "품절"로 바뀜).
3. **구매 상태가 한눈에 안 들어온다.** 구매 버튼 위에 가격, 재고, 구매 제한, 배송, 수량이 줄줄이 있고, 1인 구매 제한(`1인 2개`)은 `facts` 중간에 묻혀 있다. 수량 +/−의 `ghost` 버튼은 라이트에서 테두리가 연하다.
4. **버튼 상태 구분이 약하다.** 비활성(품절/주문 중) 버튼이 `opacity: .45`라서 "주문 중…"(진행 중)과 "품절"(구매 불가)이 같은 흐린 주황으로만 보인다. 진행 중임을 알릴 시각 단서가 글자뿐이다.
5. 모바일(product.mobile.*)에서 구매 버튼은 갤러리 → 설명 → 가격 → 재고 → 수량 아래에 있다. 화면 하나 분량은 아니지만 동작 중복 클릭 방지는 현재처럼 유지돼야 한다.
6. "같은 카테고리 상품" 섹션이 카드 1장일 때 240px 폭 카드 하나만 덩그러니 놓여 보인다(다크 PC). 기능 문제는 아님.
7. 상세 섹션 제목(`h2`)이 `2px solid var(--text)` 밑줄로 무겁다.

### 개선안
1. **구매 박스 위계** (위에서 아래): 카테고리 → 상품명(`h1` 22px) → 설명 → 가격 블록(원가 취소선, 할인율 `--accent-text`, 가격 26px) → **재고 상태 줄** → 구매 조건(`facts`: 구매 제한, 배송) → 수량 줄 → 구매 버튼.
2. **재고 상태 줄**(`.stock-line`, `facts`와 분리해서 가격 아래):
   - `stock > 10`: 아무 강조 없이 `--muted` 글자 "재고 N개" (사실만).
   - `1 <= stock <= 10`: `--warn-weak` 배경 `--warn` 글자 칩 "N개 남음". 시간, 막대, 경고 아이콘 없음.
   - `soldOut`: `--neutral-weak` 배경 + `--neutral` 글자 칩 "품절"과 아래 한 줄 "다시 입고되면 이 상품 목록에 표시돼요"는 쓰지 않는다(서버 기능이 없다). 대신 구매 버튼 글자가 "품절"이고 수량 +/−가 비활성이다(현재 동작 유지).
3. **구매 제한**이 있으면 가격 블록 아래가 아니라 수량 줄 위에 `--info-weak` 칩 "1인 2개까지"를 둔다(`facts`에서는 제거하지 않고 둘 다 두어도 된다. 구현 단순화를 위해 `facts` 유지 + 수량 줄 옆 보조 글자 `--muted` "최대 N개"를 추가해도 됨).
4. **구매 버튼 3가지 상태**: 정상(`--accent` / `--on-accent`, 높이 48px, `--fs-base`, 굵게), 진행 중(`disabled` + `aria-busy="true"`, `--accent-hover` 배경, 앞에 회전 링, 글자 "주문 중…"), 구매 불가(`disabled`, `--disabled-bg` / `--disabled-fg`, 글자 "품절"). 진행 중과 구매 불가는 **색 자체가 다르다**(투명도 차이가 아님).
5. **수량 +/−**: `--border-strong` 테두리, 버튼 40x40px, 숫자는 `tabular-nums`.
6. **상품 정보 표**: `th` 배경 `--surface-2`, 글자 `--muted`(5.38:1 / 다크 6.09:1). 행 사이 `--border`. 모바일에서 `th` 폭 120px.
7. **섹션 제목**: `h2` 18px, 아래 `1px solid var(--border)`로 가볍게. 제목 왼쪽에 4px `--accent` 막대는 쓰지 않는다(장식 최소화).
8. **모바일**: 구매 버튼과 수량 줄은 그대로 아래에 두고 높이 48px 유지. 하단 고정 바는 마크업 변경이 커서 다음 라운드 후보.
9. **관련 상품**: 1장이어도 `grid`의 열 수를 따르되 카드 폭은 목록과 같게(`minmax(200px, 1fr)` → 카드 최대 폭 240px 유지). 이미지 자리는 목록과 같은 placeholder 규칙.
10. **부가 기능 격리**: 관련 상품 영역이 비어도(`related.length === 0`) 섹션 자체를 그리지 않는 현재 동작 유지. 활동 로그, AI는 이 화면에서 쓰지 않는다.

## 4. 로그인 `/login`

### 현재 문제 (login.* 4변형을 직접 봄)
1. **대비 실패(라이트 3건)**: 헤더 회원가입 3.58:1, 카드의 "회원가입" 링크(`.auth-alt a`, accent 글자 / 흰색 3.58:1), 데모 계정 안내 문구(`--muted` / `--surface-2` 4.31:1). 다크 1건은 헤더 버튼.
2. **비활성 로그인 버튼이 탁하다.** 라이트는 연한 살구색, 다크는 칙칙한 갈색(`opacity: .45`로 accent가 배경과 섞임). 입력 전 상태에서 "무엇을 해야 활성이 되는지" 안내가 없다.
3. 입력칸 테두리가 `--border`로 매우 연하다(라이트에서 흰 카드 위 `#e2e5ea`, 약 1.3:1). 비어 있는 칸의 경계가 거의 안 보인다(login.pc.light).
4. 첫 입력칸에 포커스(accent 테두리)가 있다. 코드는 `outline: 2px` + `outline-offset: -1px`라 링이 칸 안쪽에 그려진다. 동작은 문제없고, 다른 요소(버튼, 링크)와 같은 규칙(바깥쪽 링)으로 통일한다.
5. 카드가 화면 위쪽 1/3에 떠 있고 위아래 여백이 비대칭이다(login.mobile.*: 헤더와 카드 사이 약 48px, 카드 아래 빈 공간 큼). 문제라기보다 정돈 포인트.
6. 데모 계정 영역이 카드 안에서 같은 비중으로 크게 차지한다. 데모 버튼 3개가 실제 로그인 폼만큼 눈에 띈다.
7. 에러 메시지 영역(`.form-error`)은 이번 스크린샷에 없다(에러 상태를 캡처하지 않았다). 코드상 `--bad` / `--bad-weak` 박스이며 새 토큰으로 대비 5.75:1(라이트), 6.72:1(다크)이 된다.

### 개선안
1. 카드: `--surface`, `1px solid var(--border)`, `--radius-lg`, padding `--space-5`(모바일) / `28px`→`--space-6`(PC), 폭 `min(420px, 100%)`, 위쪽 여백 `--space-6`.
2. 입력칸: 높이 44px, `1px solid var(--border-strong)`, 포커스는 `outline: 2px solid var(--focus); outline-offset: 1px`(안쪽으로 눌리지 않게 바깥쪽). `aria-invalid`면 `--bad`.
3. 라벨은 `--fs-sm` 굵게, 입력칸과 `--space-2`.
4. 제출 버튼 3상태: 정상(accent), 입력 대기(`disabled`, `--disabled-bg`/`--disabled-fg`), 진행 중(`disabled` + `aria-busy="true"`, `--accent-hover` + 회전 링 + "로그인 중…"). 입력 대기 상태가 흐린 주황이 아니라 **회색 비활성**으로 보여서 진행 중과 구분된다.
5. 에러: 버튼 바로 위에 `role="alert"` 박스(현재 위치 유지). 아이콘 없이 글자로. 에러 후 비밀번호만 비워지는 현재 동작 유지.
6. "아직 회원이 아니신가요? 회원가입": `--muted` 글자 + 링크는 `--accent-text` 굵게, 밑줄은 hover 때만이 아니라 항상(색에만 기대지 않게).
7. **데모 계정 영역**: 폼과 시각적으로 분리(`--surface-2` 면 유지, 위에 구분선), 제목 "데모 계정" `--fs-sm` 굵게, 안내 `--muted`(5.38:1), 버튼은 `ghost small` 한 줄씩 유지. 비중을 줄이려고 제목 왼쪽에 아이콘은 넣지 않는다. 운영 프로필에서 데모 영역이 노출되면 안 된다는 점은 기존 `ProductionGuard`/프론트 빌드 설정의 일이며 이 문서 범위 밖이다(데모 영역은 현재 코드 동작 그대로 둔다).
8. 모바일: 카드 좌우 여백 `--space-4`, 카드 폭 100%. 가로 스크롤 없음.

## 5. 회원가입 `/signup`

### 현재 문제 (signup.* 4변형을 직접 봄)
1. **대비 실패(라이트 3건)**: 헤더 회원가입 3.58:1, 카드의 "로그인" 링크 3.58:1, "가입하기" 버튼 3.58:1. 다크 2건은 헤더 버튼과 "가입하기" 버튼(흰 글자 / `#ff8a3d` 2.35:1).
2. 비밀번호 규칙 안내("영문과 숫자를 포함해 8자 이상")는 라벨 안에 있어 굵은 글씨로 렌더링된다(라벨 `font-weight: 600` 상속). 설명 글자가 라벨만큼 굵어 위계가 흐리다(signup.pc.light).
3. 입력칸 테두리가 연해 경계가 약하다(login과 동일).
4. 5개 입력이 모두 같은 간격이고 필수/선택 구분이 없다(전부 필수이므로 구분은 필요 없음). 검증 에러(`.field-error`, `.field-ok`)가 12px이라 모바일에서 작다. 에러 상태는 스크린샷에 없다(캡처되지 않음).
5. 가입 버튼은 항상 활성(`disabled={submitting}`만)이라, 누르면 에러가 표시되는 흐름이다. 현재 로직 유지.
6. 아이디 중복 확인 결과(`확인 중…`, `사용할 수 있는 아이디입니다`, `이미 사용 중인 아이디입니다`)가 입력칸 아래 같은 위치에 나온다. 색으로만 구분된다(`--good`, `--bad`).

### 개선안
1. 로그인과 같은 카드/입력칸/버튼 규칙(위 4번 1~4항)을 그대로 쓴다. 공통 클래스 `.auth-card`, `.auth-submit`를 공유하므로 CSS는 한 곳에서 고친다.
2. 도움말(`.muted`)은 라벨과 분리: 라벨은 굵게, 도움말은 `font-weight: 400`, `--fs-xs`(12px), `--muted`. 라벨 `<label>` 안의 `span`이므로 `.auth-card label .muted, .field-error, .field-ok { font-weight: 400 }`.
3. 검증 메시지: 글자 앞에 상태 단어를 붙여 색 의존을 줄인다. 에러는 기존 문구 그대로 `--bad` 글자(입력칸도 `--bad` 테두리), 성공은 기존 "사용할 수 있는 아이디입니다"를 `--good`로. 글자 크기 `--fs-xs`→`--fs-sm`(13px).
4. 제출 버튼: 정상(accent), 진행 중(`aria-busy`, `--accent-hover`, 회전 링, "가입 중…"). 중복 제출 방지(`disabled={submitting}`)는 그대로.
5. 카드 아래 "이미 회원이신가요? 로그인" 링크는 login과 같은 규칙(`--accent-text`, 밑줄).
6. 모바일: 입력칸 높이 44px, 간격 `--space-3`, 카드 폭 100%.
