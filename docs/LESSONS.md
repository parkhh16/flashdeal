# LESSONS.md — 시행착오 기록 (세션 시작 시 자동으로 읽힘)

> 규칙: 최대 60줄. 항목은 "증상 → 규칙" 한 쌍으로 쓴다. 해결돼 더 필요 없는 항목, 중복 항목은 지우거나 합친다.
> 갱신은 라운드 종료 시 `lessons-curator` 1회만 한다. 코더·리뷰어는 직접 고치지 말고 보고에 "교훈 후보"로 적는다.
> 출처 표기: S1 = 2026-11-21 니즈샵 UI/UX 자동 실행 세션 (한국시간 15:23~16:30).

## A. 비용(토큰) 규칙
- A1 메인 호출 1건이 약 17만 토큰을 읽는다(서브는 약 5만). 메인을 깨우는 호출을 줄인다. (S1: 캐시 읽기 24.9M 중 메인 63%)
- A2 에이전트는 라운드당 최대 6개(designer, frontend-coder, frontend-tester, frontend-reviewer, visual-reviewer, lessons-curator). 단계가 순차면 코더 1개가 끝까지 한다. (S1: 17개 호출, 단계마다 문서 재독)
- A3 백그라운드(run_in_background)는 완료를 두 번 알려 메인을 두 번 깨운다. 포그라운드를 기본으로 한다. (S1: 핸드백 17 + 알림 9)
- A4 끝나기 전에 커밋·푸시한다. 미커밋 변경은 Stop 훅으로 메인을 다시 깨운다. (S1: 훅 7회, 약 2.9M)
- A5 스크린샷은 가로 800px 이하로 줄이고 필요한 구간만 잘라 읽는다. 전체 페이지 PNG(1280×2974) 1장이 36만~56만 자였다. 대표 2장(PC 라이트, 모바일 다크)부터 본다.
- A6 라운드를 새로 열 때는 새 세션에서 시작하고 이 파일과 docs/design 문서만 넘긴다. 메인 컨텍스트가 100K를 넘으면 /compact 한다. (S1: 8만→26만, 압축 없음)
- A7 1시간 이상 자리를 비울 때는 새 세션으로 이어간다. 캐시가 만료돼 재개 첫 호출에서 컨텍스트 20만을 다시 썼다.

## B. 품질·진행 규칙
- B1 "전후가 똑같아 보인다"는 평가가 나오면 라운드 실패로 본다. 시작 전에 "눈에 보이는 변화" 기준을 적고, 끝나면 전후 비교 이미지로 증명한다. (S1: 1라운드가 11.3M을 쓰고도 변화 없음)
- B2 사이드바 같은 구조 요소를 지울 때는 먼저 사용자에게 묻는다. (S1: 2라운드에서 Sidebar 삭제 후 "사이드바 없애버린겨?" 질문. 방향 1/2/3 선택 대기 중이었음)
- B3 라운드가 끝나면 산출물 위치를 한 번에 알린다: 브랜치, 전후 스크린샷 경로(docs/design/shots/r1-after, r2-after), 비교 이미지. (S1: "진행상황과 바뀐 점 어디서 확인해?", "전후 스크린샷 경로 어떻게 본다고?")
- B4 환경이 자동 체크포인트 커밋을 만들 수 있다. 코더는 `git log`로 자기 변경이 이미 커밋됐는지 확인하고 보고한다. (S1: 단계 D 코더가 "내가 커밋하지 않았는데 HEAD에 들어 있다"고 보고)
- B5 원인을 모르는 문제는 "미확인"으로 남기고 추측으로 규칙을 만들지 않는다. (S1: 실행 중 "아무말도 입력안돼?" 현상은 원인 미확인)

## C. 이 프로젝트의 불변 규칙 (S1 지시문·리뷰 기준에서 옮김)
- C1 수정 범위는 `frontend/` 디자인만. backend, API(api.ts), 비즈니스 로직, Flyway, deploy, .github는 건드리지 않는다.
- C2 PAYING 주문은 보라 점선 박스와 "결제 확인 중" 글자로 표시하고, 취소·재결제 버튼을 두지 않는다. 확정(완료/실패)처럼 보이면 안 된다.
- C3 상품 상세의 구매 버튼은 DOM에 하나만 둔다(고정 구매 바와 패널에 중복 렌더 금지). `inFlight` ref 가드와 `disabled` 조건을 유지한다.
- C4 기준선: `npm run build` 통과, `npm run lint` 경고 24개 이하(1라운드 종료 26 → 사이드바 삭제 후 24), `npm run e2e`는 직전 기준 통과 153 / 실패 2(admin-activity 모바일 라이트·다크의 scrollable-region-focusable). 새 실패를 만들지 않는다.
- C5 새 의존성은 추가하지 않는다. package.json 변경은 스크립트 한 줄 수준으로 제한한다.
